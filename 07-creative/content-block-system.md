# Modular Content Block System

## Thesis

Lifecycle creative should be reusable without becoming generic.

A modular content system lets teams move faster, preserve brand quality, and learn which messaging territories actually work.

## Core Structure

Build a library of reusable blocks for:
- hero headline
- preheader / supporting line
- benefit statement
- clinical / expert proof
- social proof
- objection handling
- value framing
- urgency
- CTA
- product-specific proof

Each block should have multiple approved copy variants so marketers can assemble different emails without starting from a blank page.

## Why It Works

This solves three common problems:

### 1. Creative bottlenecks
Design and copy do not need to rebuild every message from scratch.

### 2. Inconsistent brand voice
Approved modules create guardrails while still allowing variation.

### 3. Slow learning
Messaging territories can be tested repeatedly across campaigns and flows.

## Operating Model

1. Creative develops reusable visual modules.
2. Copy creates a bank of approved headlines, claims, proof points, CTAs, and support copy.
3. Lifecycle assembles modules based on audience and objective.
4. Campaigns test combinations and territories.
5. Durable winners migrate into evergreen automation.

## Copy Bank Standards

Every copy bank should include:
- short / medium / long variants
- product-specific variants
- audience-specific variants
- proof-led variants
- benefit-led variants
- value-led variants
- urgency variants
- CTA variants

For regulated categories, each block should also indicate:
- approved claim language
- required substantiation or disclaimer
- restricted language

## Principle

The goal is not template sameness. The goal is controlled modularity: faster production, stronger consistency, and a system that compounds learning over time.
